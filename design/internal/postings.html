“Post an approved requisition” → the picker

There is no blank “new posting” form

Nothing can be advertised that the business has not approved, and one requisition produces exactly one posting. Both are enforced in the service and by a unique index, so the UI does not need to be the guard — but if it offers a blank form, every recruiter will meet the guard as an error message instead of as a rule.

Minted once, kept forever

Unpublishing and republishing returns the same token. Someone has already pasted this into a Facebook group; a re-issued link would turn that post into a dead end and the recruiter would never find out. The token is a Sqid (ADR-0020), so it is short enough to read aloud and does not expose a sequential id.

The key is shown and cannot be edited. It is the JSONB key the answers live under, so renaming it would orphan every answer already collected. Showing it read-only teaches that in one glance; hiding it means the first person to ask for a rename gets a refusal with no explanation.

File upload is present but disabled, with its reason in the tooltip. It is a real field type in the plan, blocked on ADR-0013. Omitting it entirely would make it look unconsidered.

Closing is not deleting

Closing a posting stops new applications and leaves the link resolving to a “this role has closed” page. The 61 people who applied to the Treasury Dealer role still have their applications, and anyone reopening that link gets an answer rather than a 404.
