This deployment cannot receive messages

Viber, Telegram and Facebook deliver by calling a webhook. This install sits behind the corporate firewall and has no publicly reachable endpoint, so nothing can call in. Connecting a bot here would appear to work and would silently receive nothing.

Three ways out, none of them decided

Publish an endpoint

A single inbound path through the DMZ. The customer's security team owns that decision, not us.

Hosted tier only

Sourcing channels become a reason to choose hosted. Clean, but it makes the headline differentiator unavailable to the on-prem buyers who want it most.

Outbound polling

We call out instead of being called. Works behind a firewall; Telegram supports it, Facebook does not.

Everything below is drawn as it would look once one of these is chosen. It is shown greyed rather than hidden so a sales conversation can point at the real screen and at the real reason it is off.

Which job is this person applying for?

A web form knows, because the form belongs to a posting. A chat message does not. Three answers, in the order the system should try them.

1

The link carried it

A deep link or QR code from the posting: t.me/yomabank_jobs?start=U9kL3mQx. The token is the posting's own public token, so a QR on a branch poster and the link in a Telegram post resolve to the same job with no extra mapping.

2

The post it came from

A Messenger reply inherits the Facebook post id, and that post was published by a posting. Inferred, never asked.

3

Ask, with buttons

Only when 1 and 2 both fail. Live positions as inline buttons, never a free-text question — a typed answer in Burmese would have to be matched back to a posting, and that is a worse problem than the one being solved.

Open on board

Two questions, then stop

The module doc asks whether the bot is a form or a conversation. Drawn as: the bot collects what routing and dedup need, then hands over. A ten-question chat form has the drop-off of a long form and none of its clarity — and every question asked in chat is another Burmese free-text answer somebody has to parse.

Same dedup as the web form

09-95xxxxxx is checked against existing candidates exactly as an application from the career page would be. Filtering duplicate CVs out of social traffic is a headline benefit of this module, and it only works because there is no second intake path.

The recruiter can type

Automated replies are labelled automated so a human reply is visibly different. A candidate who asks something the bot cannot answer must reach a person without leaving the thread.

Status notifications going out

The half of this module candidates actually feel: being told what happened. It is also the half that becomes spam if it is switched on without care.

Notify on stage change

  • Application received

    Sent once, immediately. The message that stops the “did you get it?” follow-ups.

  • Interview scheduled

    Date, time and place, in the language they wrote in.

  • Moved to Screening / Shortlisted

    Off by default. Internal stage names are not news to a candidate, and “Shortlisted” raises an expectation the pipeline has not earned yet.

  • Not proceeding

    Off by default and deliberately not automatic. An automated rejection over Viber, in a market this small, is the message that gets screenshotted.

Opt-out is on every outbound message

Consent and opt-out are hard requirements of this module. Once someone opts out the flag lives on the candidate, so it survives them applying again through a different channel — otherwise the opt-out is per-conversation and means nothing.

A failure row says what to do next

“Failed” alone makes a recruiter open a support ticket. Facebook's 24-hour rule is a policy, not an outage, and it will recur every week — so the row names the rule, states the consequence in the candidate's terms, and suggests the fallback. The same applies to an opt-out: Not sent is a correct outcome, and it is styled as neutral rather than as an error.
