Manage user → the control that is not a permission

Department scope

ADR-0003 makes department scoping the security-critical filter — the one applied explicitly in each query, and therefore the one that can be forgotten. It is not a permission and it is not stored on the role, so it gets its own panel with its own language, never a row in the matrix above.

Can act in

Why this reads “can act in”, not “can see”

The scope governs every verb the role grants, not just reading. A hiring manager scoped to Credit Risk cannot move a Retail candidate either. Labelling it “visibility” would teach admins the wrong model, and they would grant it too freely.

The empty-scope trap

Untick both and the account still holds eleven permissions and reads nothing — a state that looks like a broken app rather than a configuration. Saving with an empty scope should ask for confirmation and say so in those words. Not drawn as settled: whether empty scope is legal at all is a backend question this design cannot answer alone.

Tenant is not on this screen

One instance per company (ADR-0004), so there is no tenant picker and no cross-company assignment. The tenant filter exists in code as a dormant safety net; putting it in the admin UI would imply a shared deployment that does not exist.
