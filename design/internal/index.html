Static HTML instead of Figma, so the Tailwind classes transfer straight into frontend/internal and frontend/public rather than being re-drawn. Tokens are V1.0 (ADR-0025) and live in one place: ds.js. 26 screens covering all seven modules.

Shell: Board / Workspace

The pipeline board is the app's home surface; records open from it rather than sitting beside it in a menu. Chosen from a three-way roll on 2026-08-17. Its known risk, recorded at the time: requisition governance is this product's real differentiator, so the board must not bury Module 1. The board's top bar answers that — it always names the requisition it exists because of, shows its status, and keeps the chain one click away.

Try these

  • On the board, switch Density to Compact — one control, both audiences.
  • On the interview screen, press Submit evaluation — the panel's scores are absent until then, not blurred.
  • On the requisition, expand Round 1 · Rejected — the reason survives the revision.
  • On Users & roles, select the Admin role — the matrix is read-only, because the role bypasses it.
  • On Channels, read the red panel first — the feature is off for a deployment reason, not a build one.

How these differ from the landing page

That page is Persuade — it exists to make someone decide. These are Operate: someone is mid-task. So there is no page-load choreography, one type family instead of a display pairing, no themed scrollbars, motion only where it reports state, and every control ships its full set of states. Familiarity is the goal, not surprise.

What these screens found in the specs

Drawing a screen forces a question a document can leave open. Five that need a human answer:

  • The threshold rule has nowhere to live. Three screens show an approver “added by threshold rule”; ApprovalChain has no condition field. Either it gains one, or those three screens are wrong.
  • An approval step names a person, not a role. Disabling a user can silently stall every requisition behind them, and nothing in the data links the two.
  • Module 8 may be impossible on-premise. Webhooks need a public endpoint. Publish one, sell it hosted-only, or poll — undecided, and it is the headline differentiator.
  • Module 6 needs Requisition → HeadcountPlan. Without it, “are we over headcount?” can only be answered by hand.
  • Age and gender filters are unconfirmed. Held behind a click with the open question attached, rather than shipped as ordinary filters.

Still not drawn

JD templates (Module 1), the audit-log viewer, and notification preferences. Nothing below 505px has been rendered at any point in this build, so true phone widths need checking on a real device — the public screens are designed phone-first but verified only from 505px up.
